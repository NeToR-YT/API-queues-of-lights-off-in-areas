## 0.1 Ротація Telegram-акаунта

Чинний `session_string` лежав у git і **вважається скомпрометованим**.
Видалення з індексу його не рятує: він лишається в історії комітів і в усіх форках.

1. **Новий акаунт.** Окрема SIM/номер, не особистий Telegram. Увімкнути 2FA
   (Settings → Privacy and Security → Two-Step Verification).
2. **Свої API-креденшали:** https://my.telegram.org → API development tools →
   отримати `api_id` і `api_hash`.
3. **Відкликати стару сесію** у старому акаунті:
   Settings → Devices → **Terminate all other sessions** — у git витекли ДВІ сесії:
   `session_string` на `production` і Telethon-файл `backend/session_name.session` на `back`.
   Зробити це **до** того, як новий стек піде в роботу.
4. **Прописати нові значення** у `.env` (`TG_API_ID`, `TG_API_HASH`)
   і стерти `backend-js/secrets/session.txt`.
5. **Перший вхід** створить нову сесію у файлі-секреті:
   ```bash
   docker compose run --rm -it backend node dist/app.js
   ```
6. Підписати новий акаунт на всі 23 канали (парсер читає лише те, що доступне).

> Новий акаунт чутливіший до flood-банів. Перші дні — без агресивного парсингу:
> `batch_delay` не зменшувати, канали не тягнути паралельно.

## 0.4 Дефолтна гілка GitHub

Зараз дефолтна — `back` (мертвий прототип), робоча — `production`.
За новим git-флоу дефолтною стає **`main`** (= нинішній `production`), поруч — `develop`.
Повна процедура переходу з архівними тегами — `CONTRIBUTING.md`, розділ «Перехід на цю схему».

## Зачистка історії git (окремо, після 0.1)

Поки старий `session_string` не відкликаний, чистити історію сенсу нема.
Після ротації — прогнати `git filter-repo` або BFG по `backend-js/config.json`
і зробити force-push. Це переписує історію: узгодити окремо, бо ламає всі клони
й форки. До того моменту вважаємо старі креденшали публічними.
