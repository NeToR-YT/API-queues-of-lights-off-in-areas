# СвітлоUA

Відкритий API графіків погодинних відключень світла (ГПВ) для 23 областей України.

Обленерго публікують графіки в Telegram-каналах, кожне у своєму форматі й з оновленнями
посеред дня, а машиночитаного API немає. СвітлоUA збирає ці пости, розбирає черги й
інтервали та віддає їх через REST API: розклад на сьогодні й завтра, історію і статистику
за період.

Фронтенд: https://nadlaf.github.io/LightUA/

## Можливості

- Розклад по області й черзі на сьогодні, на завтра або на будь-яку дату з історії.
- Статистика: скільки годин без світла, надійність у відсотках, теплові карти по годинах
  і днях тижня, порівняння черг. Специфікація: [`docs/stats-api.md`](docs/stats-api.md).
- Ознака аварійних відключень, яка враховує заперечення на кшталт «аварійні відключення скасовано».
- Інкрементальний збір: щоразу читаються лише нові пости.

```bash
curl "https://<домен>/api/schedules/today?channel_id=1"
```

```json
{
  "channel_id": 1,
  "city_name": "Черкаська область",
  "date": "2026-11-09",
  "time": "21:40:05",
  "schedule": { "1.1": ["00:00-04:00", "12:00-16:00"], "1.2": ["04:00-08:00"] },
  "emergency_outages": false
}
```

## Архітектура

```
Telegram-канали обленерго
        │  MTProto, user-акаунт
        ▼
 ┌──────────────┐      ┌─────────┐      ┌────────────────┐      ┌───────┐
 │ парсер       │─────▶│ MongoDB │◀─────│ API            │◀─────│ Caddy │◀── HTTPS
 │ без портів,  │ пише │         │ читає│ /api/*, /v1/*  │      │ + TLS │
 │ ізольований  │      └─────────┘      └────────────────┘      └───────┘
 └──────────────┘
```

Парсер не відкриває жодного порту й тримає Telegram-сесію в окремому контейнері, тож навіть
злам публічного API не дає доступу до сесії. Рішення та їхні компроміси описані в [ADR](docs/adr/).

## Стан проєкту

| Частина | Стан |
|---|---|
| `backend-js/`: TypeScript, Express, GramJS | працює в релізі `v0.10.0`, поступово замінюється |
| `parser/`: Python, Telethon | у розробці, логіка розбору готова й звірена зі старим парсером |
| `platform/`: Python, FastAPI | заплановано: `/v1` і сумісний `/api/*` |

Чому проєкт переходить на Python, пояснює [ADR-0002](docs/adr/0002-python-backend.md),
модель даних описана в [ADR-0003](docs/adr/0003-data-model-v2.md).

## Локальний запуск

Потрібні Docker і власні ключі Telegram API з https://my.telegram.org.

```bash
cp .env.example .env                                     # TG_API_ID, TG_API_HASH
cp backend-js/config.example.json backend-js/config.json # канали обленерго
docker compose up -d --build
```

API відповідатиме на `https://localhost/api/` із самопідписаним сертифікатом Caddy.
Розгортання на сервері: [`docs/deploy.md`](docs/deploy.md), акаунт для парсера:
[`docs/telegram-account.md`](docs/telegram-account.md).

Тести Python-парсера:

```bash
cd parser && uv sync && uv run pytest
```
