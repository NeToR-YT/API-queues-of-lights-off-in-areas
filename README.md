# СвітлоUA

**Відкритий API графіків погодинних відключень світла (ГПВ) для 23 областей України.**

Обленерго публікують графіки в Telegram-каналах — щоразу у своєму форматі, з оновленнями
посеред дня, без машиночитаного API. СвітлоUA збирає ці пости, розбирає черги й інтервали
і віддає їх через REST API: розклад на сьогодні й завтра, історію і статистику за період.

Бойовий фронт: **https://nadlaf.github.io/LightUA/**

## Що вміє

- Розклад по області й черзі: на сьогодні, на завтра, на будь-яку дату з історії
- Статистика: скільки годин без світла, надійність у відсотках, теплові карти по годинах
  і днях тижня, порівняння черг — специфікація в [`docs/stats-api.md`](docs/stats-api.md)
- Ознака аварійних відключень з урахуванням заперечень («аварійні відключення скасовано»)
- Інкрементальний збір: читаються лише нові пости з моменту останнього циклу

```bash
curl "https://<домен>/api/schedules/today?channel_id=1"
```

```json
{
  "channel_id": 1,
  "city_name": "Черкаська область",
  "date": "2026-11-09",
  "time": "21:40:05",
  "schedule": { "1.1": ["00:00-04:00", "12:00-16:00"], "1.2": ["04:00-08:00"] },
  "emergency_outages": false
}
```

## Архітектура

```
Telegram-канали обленерго
        │  MTProto, user-акаунт
        ▼
 ┌──────────────┐      ┌─────────┐      ┌────────────────┐      ┌───────┐
 │ парсер       │─────▶│ MongoDB │◀─────│ API            │◀─────│ Caddy │◀── HTTPS
 │ без портів,  │ пише │         │ читає│ /api/*, /v1/*  │      │ + TLS │
 │ ізольований  │      └─────────┘      └────────────────┘      └───────┘
 └──────────────┘
```

Парсер не слухає жодного порту і тримає Telegram-сесію в окремому контейнері: злам
публічного API не дає доступу до сесії. Деталі й компроміси — в [ADR](docs/adr/).

## Стан проєкту

| Частина | Стан |
|---|---|
| `backend-js/` — TypeScript, Express, GramJS | **працює**, реліз `v0.9.0`; поступово замінюється |
| `parser/` — Python, Telethon | у розробці: домен розбору готовий і звірений зі старим парсером |
| `platform/` — Python, FastAPI | заплановано: `/v1` + сумісний `/api/*` |
| `frontend/` — React | тестовий клієнт для локальної розробки |

Чому перехід на Python і як він влаштований — [ADR-0002](docs/adr/0002-python-backend.md),
модель даних — [ADR-0003](docs/adr/0003-data-model-v2.md).

## Запуск локально

Потрібні Docker і власні Telegram API-ключі з https://my.telegram.org.

```bash
cp .env.example .env                                     # TG_API_ID, TG_API_HASH
cp backend-js/config.example.json backend-js/config.json # канали обленерго
docker compose up -d --build
```

API — на `https://localhost` (самопідписаний сертифікат Caddy). Деплой на сервер —
[`docs/deploy.md`](docs/deploy.md).

Тести Python-парсера:

```bash
cd parser && uv sync && uv run pytest
```
