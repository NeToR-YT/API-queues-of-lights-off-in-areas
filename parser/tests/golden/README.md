# Golden-корпус

Еталон поведінки парсера: Python-версія має відтворювати ці результати.

```
raw/       сирі повідомлення каналів, JSONL: {message_id, date, text}
expected/  що з них зробив старий парсер (backend-js/src/parser.ts)
```

## Як перезібрати

```bash
cd backend-js
npm run corpus:export     # 1. знімає повідомлення з Telegram (потрібна сесія)
npm run corpus:expected   # 2. рахує еталон, мережа не потрібна
```

Перший крок ходить у мережу, тому йому потрібна робоча сесія Telegram. Другий
детермінований, його можна запускати скільки завгодно.

## `0-sample.jsonl`

Три синтетичні повідомлення для швидкої перевірки самого конвеєра, поки реального
корпусу немає. Покривають однорядковий і багаторядковий формат черги, різні види тире
та заперечення аварійних відключень. Реальний корпус лягає поруч, а не замість.

## `0-formats.jsonl`

Синтетичні пости на всі відомі формати. Еталон для них рахує справжній TS-парсер, тож
Python можна чесно звірити з TS ще до появи реального корпусу. Поле `reference_date` в
еталоні фіксує день генерації: від нього залежить рік у датах, де рік не вказаний.

## Важливо

`expected/` показує, як поводився старий парсер, а не як правильно. Старий парсер
місцями помиляється. Якщо новий свідомо дає інший результат, розбіжність описується в
ADR або в коментарі до тесту. Мовчки підганяти еталон під новий код не можна.
