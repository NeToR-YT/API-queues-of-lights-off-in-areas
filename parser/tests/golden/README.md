# Golden-корпус

Еталон поведінки парсера. Python-домен (задача 1.3) має відтворити ці результати.

```
raw/       сирі повідомлення каналів, JSONL: {message_id, date, text}
expected/  що з них зробив СТАРИЙ парсер (backend-js/src/parser.ts)
```

## Як перезібрати

```bash
cd backend-js
npm run corpus:export     # 1. знімає повідомлення з Telegram (потрібна сесія)
npm run corpus:expected   # 2. рахує еталон; мережі не потребує
```

Крок 1 — мережевий і потребує чинної сесії, тож виконується **після ротації
акаунта** (задача 0.1). Крок 2 детермінований: перезапускати можна будь-коли.

## `0-sample.jsonl`

Синтетичний зразок на три повідомлення — димовий тест самого конвеєра, щоб
`corpus:expected` можна було ганяти ще до появи реального корпусу. Покриває
однорядковий і багаторядковий формат черги, тире-варіанти та заперечення
аварійних відключень. Реальний корпус його не замінює — додається поруч.

## `0-formats.jsonl`

Синтетичні пости на всі відомі формати. Еталон для них рахує справжній TS-парсер, тож це
чесна звірка Python із TS ще до появи реального корпусу. `reference_date` в еталоні фіксує
дату генерації: від неї залежить рік у датах без року.

## Важливо

`expected/` — це знімок поведінки старого парсера, **не визначення правильності**.
Старий парсер місцями помиляється. Там, де новий дає інший результат свідомо,
розбіжність фіксується в ADR або коментарі до тесту — і ніколи не «підганяється»
мовчки під старий вихід.
